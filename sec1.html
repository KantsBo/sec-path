Search Skills

Где аналитик ищет информацию об угрозах и уязвимостях.

VirusTotal каждый день

70+ антивирусов в одном окне. Проверяет файл, ссылку, домен, хэш.

✅ Проверяй по хэшу, файл не загружай. Иначе документ компании окажется в общем доступе.
⚠️ 0 из 70 не значит «чисто». Вирус может быть новым.

⚠️ Чужой PoC может быть сломан или сам оказаться вирусом. Читай код до запуска.

03

Основы Windows

Файловая система, журналы событий, команды и встроенная защита.

NTFS и скрытые потоки ADS

наизусть

NTFS = файловая система Windows. Журналируемая (после сбоя восстанавливается сама), файлы больше 4 ГБ, права доступа, сжатие, шифрование EFS. До неё были FAT16/FAT32 и HPFS.

Права (ПКМ → Свойства → Безопасность): Full control · Modify · Read & Execute · List folder contents · Read · Write

SOCВредоносы прячут данные в ADS. Обычное применение: метка «файл скачан из интернета».

Папка ОС: %windir% = C:\Windows. Внутри System32: критичные файлы, удалять нельзя.

Другие важные разделы

понимать

Встроенная защита Windows

Security+

Defender

Антивирус. Угрозы уходят в карантин. Защита в реальном времени блокирует запуск.

Controlled folder access

Защита от вымогателей (ransomware): менять папки могут только доверенные программы.

Exclusions

Что антивирус не проверяет. Добавлять опасно, только при 100% уверенности.

Firewall: 3 профиля

Domain (сеть компании) · Private (дом) · Public (кафе, аэропорт, по умолчанию)

Memory integrity

Изоляция ядра: вредонос не пролезет в важные процессы.

TPM

Отдельный чип для шифрования. Вредонос не может его изменить.

SOCVSS (теневые копии) хранит резервные снимки диска. Вымогатели первым делом удаляют теневые копии, чтобы жертва не восстановила файлы.

Статусы Windows Security: зелёный = защищено, жёлтый = есть совет, красный = срочно.

Мелочи

справка
  • Автозагрузка: Windows 10/11 через taskmgr, Server через shell:startup
  • Переменные среды: %windir%, ComSpec = %SystemRoot%\system32\cmd.exe
  • Файл подкачки = виртуальная память. При «синем экране» пишется дамп %SystemRoot%\MEMORY.DMP
Проверь себя

Скрытый дополнительный поток данных у файла в NTFS. Проводник его не видит, поэтому вредоносы прячут там данные.

Error, Warning, Information, Success Audit, Failure Audit.

В журнале Security, тип события Failure Audit.

netstat -a -n -o (с -b ещё и имя программы).

Теневые копии позволяют восстановить файлы. Без них жертве остаётся платить выкуп или искать внешний бэкап.

Локальных пользователей и группы.

Скрытые административные общие папки. Видны в Shared Folders.

04

Active Directory

Как компания управляет сотнями компьютеров и сотрудников из одного места.

Главная идея на одной схеме

наизусть

Домен

Все пользователи и ПК компании под общим управлением.

Active Directory

Общая база учёток. Вход на любом ПК: THM\Administrator

DC

Сервер, где работает AD.

SOCDC = самая ценная цель в сети. На нём хэши паролей всех пользователей домена.

Кто живёт в AD

наизусть

Users

Люди (сотрудники) и сервисные учётки для служб вроде IIS, MSSQL.

Computers

Учётка с паролем из ~120 символов. Узнаёшь по $: ПК DC01 → DC01$

Security Groups

Выдать права сразу пачке людей, а не каждому.

Всех их называют Security Principals: они могут входить и получать права.

OU или Группа? Частая путаница

наизусть

📁 OU (папка)

  • Для политик и настроек (GPO)
  • Обычно = отдел: IT, Sales, HR
  • Пользователь только в одной OU

👥 Группа

  • Для доступа к ресурсам: папки, принтеры
  • Не зависит от отдела
  • Пользователь во многих группах

Делегирование: дать права на одну OU обычному сотруднику. Например, техподдержка сбрасывает пароли отделу продаж, но не становится Domain Admin.

OU защищены от удаления. Чтобы удалить: View → Advanced Features → снять галочку в свойствах.

05

Kerberos и NetNTLM

Как сервер узнаёт, что ты это ты, если твой пароль знает только контроллер домена.

🎟 Kerberos

Современный, стоит по умолчанию. Работает на билетах.

🔄 NetNTLM

Устаревший, для совместимости. Работает по схеме загадка → ответ.

Kerberos = парк аттракционов

наизусть

Домен = парк. KDC на контроллере домена = главная касса. Паспорт (пароль) показываешь один раз, дальше ходишь по билетам.

  1. Ты→KDC Отправляешь имя и время, зашифрованные твоим паролем. Получаешь TGT (главный браслет) и ключ сессии. TGT запечатан хэшем учётки krbtgt: ты не можешь его открыть или подделать.
  2. Ты→KDC Показываешь TGT и называешь нужный сервис (SPN, например MSSQL/SRV). Получаешь TGS: билет на этот аттракцион. Пароль больше не вводишь. TGS запечатан хэшем владельца сервиса.
  3. Ты→Сервис Отдаёшь TGS. Сервис открывает его своим ключом и пускает. Сервис верит, потому что билет выдала касса.
ТерминПростыми словами
KDCКасса на DC, выдаёт билеты (Key Distribution Center)
TGTГлавный браслет: билет на получение других билетов
krbtgtУчётка, хэшем которой запечатан TGT
SPNИмя нужной службы и сервера (Service Principal Name)
TGSБилет на конкретный сервис

NetNTLM = загадка на входе

наизусть
  1. Ты→Сервер«Привет, пусти меня».
  2. Сервер→ТыСлучайное число-загадка: Challenge.
  3. Ты→СерверСмешиваешь NTLM-хэш пароля с загадкой и отправляешь Response.
  4. Сервер→DCСам проверить не может: пересылает Challenge и Response.
  5. DC→СерверDC повторяет расчёт со своим хэшем и сравнивает. Совпало = пустить.
🎯 Главное для экзамена: при NetNTLM ни пароль, ни его хэш не идут по сети.

Локальная учётка (не доменная): сервер проверяет сам по своей базе SAM, без DC.

Проверь себя

TGT = главный браслет, на него получают другие билеты. TGS = билет на один конкретный сервис.

Хэшем служебной учётки krbtgt.

Имя службы и сервера, к которому хочешь попасть. Например, MSSQL/SRV.

Нет. Ни пароль, ни хэш. Идут только загадка (Challenge) и ответ (Response).

Сам сервер, по своей базе SAM. Контроллер домена не участвует.
